# Funnel presentation

Fetch distinct session counts reaching each stage before rendering. For a depth histogram, stage N is the sum of sessions with depth ≥ N. Use total sessions as the baseline; skip intermediate stages that are not measured and explain why when material.

Keep stage, distinct sessions, share of baseline, share of preceding measurable stage, prior-period count/rate, and change available. Full reports use the connected vertical funnel with Show exact counts; focused textual answers can use a table. Use "not measured" for unsupported stages, not zero. Express checkout can skip payment submission; do not force observed counts to be monotonic by rewriting the data. Declare the rate denominator beside the chart. Current/prior bars share a linear scale; a pale comparison mark requires a real prior count, not an invented lost-traffic quantity.

For full topical reports, use [native presentation](presentation.md) for the measured funnel and supporting action controls. A focused funnel request can use that chart alone. Use counts and labels from the table and show the actual domain/window. A static chart is a report snapshot; saving/refreshing/scheduling are separately executed actions. Never fabricate a live dashboard or substitute a generic diagram for an actual Noibu heatmap.
